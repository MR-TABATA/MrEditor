# MrEditor

[English](README.md) | **日本語**

**自分が書いていないテキストを、調べて、正す Mac のエディタ。**

ログ、CSV、エクスポート、ダンプ、差分。どこかから降ってきたテキストです。だから大きさも文字コードも、
どれだけ読みにくいかも、こちらでは選べません。MrEditor は、それを開いて、絞って、桁を揃えて、見比べて、
直して、ファイルを半端な状態にせずに保存します。

補完も LSP も無いのはそのためです。これはコードを**書く**ための道具ではなく、
**何が起きたのかを突き止めて、直す**ための道具です。

国税庁の法人番号 全件データ CSV ―― **1.18GiB・581 万 6535 行** ―― が **51ms**・**78MB** で開きます。
Excel は同じファイルを開いて **104 万 8576 行**で止まります。仕様上の上限で、約 60 秒と 2.24GB を使って
476 万 7959 行を落とし、警告は出ません。（2026-08-03・配布版 1.10.2 で計測。Numbers は 8 分待っても開きませんでした。）

サイズは芸ではなく、下限です。**10GB・86,420,337 行**のログでも表示開始まで **約 80ms**、
`vmmap` が報告する dirty は **0 バイト**、末尾行へのジャンプは **0.1ms**。
ファイルが大きくなっても、アプリの側では何も変わりません。

> はじめは高速な**読み取り専用**ビューアでした（全文検索・フィルタ表示 / live grep・`tail -f`）。
> **v0.4 で名前どおりに** ―― その場で編集して保存できます。

そして、**増え続ける 10GB のログを `tail -f` しながら（⌥⌘F）その場で編集できます** ―― リロードせず、
mmap の索引を増えたバイトぶんだけ継ぎ足して追うので、まだ書き込まれ続けている 10GB でも破綻しません。
tail できるエディタ（BBEdit・サクラ）はファイルを読み直し、10GB までスケールするログビューア（klogg・lnav）は
読み取り専用です。**「10GB を増分で追いながら、その場で編集」は、調べた限り他に見当たりませんでした。**

## なぜ作るのか

macOS でテキストを表示する定番は `NSTextView` ですが、内部の `NSTextStorage` に
**全文を保持**します。10GB を渡すと破綻する。そこで MrEditor は巨大ログビューア
（klogg / glogg / lnav）の定石を採ります。

- ファイルは **mmap**。全文をメモリに乗せない。
- **疎な行インデックス**を持つ（2,000 行ごとに行番号とバイトオフセットを 1 組 → このファイルで 670KB、1 億行でも約 800KB）。
- **見えている行だけ** Core Text で描く。スクロールは「行」単位の自前 `NSScroller` で表現し、
  16 億ポイントの巨大ビュー（float 精度の崖）を作らない。

設計の詳細は [docs/ARCHITECTURE_v0.1.md](docs/ARCHITECTURE_v0.1.md) を参照してください。

**ツールバー** — 既定の 6 つが、このアプリが何者かの宣言
- **構造化表示・フィルタ・比較（diff）・末尾追従（`tail -f`）・AI 診断**、それにサイドバー開閉。
  どれも以前はメニューとショートカットの中にあり、起動しただけの人にとっては存在しないのと同じだった。
- 検索・保存・行ジャンプ・フォント拡縮は**あえて既定に入れていない**。⌘F と ⌘S は誰でも知っていて
  発見性の価値が無く、並べると途端に「よくあるエディタ」の顔になるため。
  **「ツールバーをカスタマイズ…」**から他の機能ごと引き出せる。
- 窓が狭いと右から » に畳まれるので、**AI 診断が最初に消え、構造化表示が最後まで残る**。
  並び順がそのまま優先順位。

**表示**
- 任意サイズの巨大テキストを開ける（10GB で検証済み）。表示開始はほぼ一瞬。
- 文字コードの自動判定：**UTF-8 / Shift-JIS / EUC-JP**（実ファイルで確認済み）。
- 行単位の自前スクローラとキーボード操作（矢印・ページ・Home/End）。
- **行番号ジャンプ（⌘L）** と **フォント拡大縮小（⌘+ / ⌘- / ⌘0）** — 起動をまたいで保持。
- **末尾追従（`tail -f`・⌥⌘F）** — ファイルが伸びると自動スクロール。**リロードせず索引を増分拡張**して追うので、
  10GB の増え続けるログでも破綻しない（編集を始めると一旦停止、保存で再開）。
- 可視範囲のコピー（⌘C）。ステータスバー：文字コード・行数・サイズ・索引進捗。

**編集（v0.4 で追加）**
- **サイズを問わず編集・保存** — 小さいファイルは `NSTextView` に読み込み、巨大ファイルは
  mmap 上の **piece table** で編集。10GB でも入力に追従します。
- **atomic 保存** — 一時ファイルに書いてから入れ替え。元ファイルが中途半端に壊れることがありません。
- **保存エンコードの指定** — **UTF-8 / Shift-JIS / EUC-JP** へ変換。改行はファイルの EOL（LF / CRLF）へ正規化。
- 新規（⌘N）・保存（⌘S）・別名で保存（⌘⇧S）・保存済みへ戻す。

**ワークスペース**
- **複数ファイルを同時に開いて**、**サイドバー**のリストで切り替え。
- **サイドバーから閉じる** — 各行に閉じる（×）ボタン。**未保存のドキュメントは色分け**表示。
- **セッション復元（v0.7 で追加）** — 起動すると前回のサイドバーが並び直ります（順序と
  アクティブなタブも復元。消えたファイルは読み飛ばし）。**未保存の新規ドキュメントも本文ごと復元**
  するため、終了時に新規タブの保存を促されることはありません（保存済みファイルの未保存編集は
  従来どおり確認します）。
- **最近使った項目**（ファイル ▸ 最近使った項目を開く）。
- ウィンドウへのファイルのドラッグ＆ドロップで開く。
- **Finder 統合（v0.8 で追加）** — Finder の「このアプリケーションで開く」に MrEditor が並びます
  （`.log` / `.txt` / `.csv` / `.json` など。既定のアプリは奪いません）。
- **印刷・PDF 出力（v0.8 で追加）** — ファイル ▸ プリント…（⌘P）。プリントダイアログの
  「PDF ▸ PDF として保存」で PDF になります。巨大ファイルは数百万ページになるため無効です。
- **アップデート確認（v0.8 で追加）** — 新しい版が出たら知らせます（起動時・1日1回まで）。
  置き換えはせず、ダウンロードページを開くだけ。環境設定 ▸ 一般 でオフにできます。

**カスタマイズ（v0.5 で追加）**
- **フォント** — 任意の等幅ファミリとサイズを選択（環境設定 ▸ 表示）。起動をまたいで保持。
- **表示** — タブ幅（2/4/8）・行間・現在行ハイライト・カーソル形状（バー/ブロック/アンダーライン）・折り返し。
- **配色テーマ** — System（ライト/ダーク自動）・Solarized Dark / Light・Monokai・Dracula・Nord・Grass・Red Sands・完全カスタム。本文だけでなく
  **周辺 UI（サイドバー・ガター・ステータス・タイトルバー）** まで連動。
- **背景の不透明度** — ウィンドウ全体を半透明にして背後のデスクトップを透かす（iTerm 風・環境設定 ▸ 配色）。
- **ANSI カラー** — ログ中の ANSI エスケープ（`ESC[…m`）を色に変換して表示（閲覧時・エスケープ列は自動で除去）。

**検索**（⌘F）— mmap をストリーム走査。ファイルを読み込まない
- 可視行の即時ハイライト＋背景の全文走査で正確な件数（一致行は上限100万）。
- **複数語 AND**（スペース区切り）・**正規表現**（`.*` トグル。**先読み・後読み**アサーション対応）・**大文字小文字の区別**トグル。
- 次/前へ移動して各一致行へジャンプ。
- **フィルタ表示 / live grep** — 一致行だけ表示（元の行番号は保持）。
  **1.11 からサイズを問わない**。それまでは巨大ファイル専用で、実際に編集する数 KB のファイルでは
  灰色のままだった。フィルタ中は読み取り専用で、絞り込んだまま保存しても**書き出されるのは
  元の本文全部**（見えている行だけではない）。
- **パイプと gzip をそのまま受ける（1.13.0 から）** — `kubectl logs -f pod/api | mreditor` で
  流し込めます（`sh scripts/install-cli.sh` で `mreditor` コマンドを入れると使えます）。
  `app.log.gz` も `logs.zip` も、ダブルクリックでもコマンドでも展開してから開きます（zip に
  複数入っていれば、名前を並べてどれを開くか訊きます）。**判定は中身**で
  行うので、`.log` のまま gzip されたファイルも開きますし、`.gz` なのに素のテキストなら
  そのまま開きます。読み切ってから開くので、途中まで見せて「これで全部」の顔はしません。
- **しおり（1.13.0 から）** — `⌘B` で今の行に印を付け、`⌘'` / `⇧⌘'` で前後のしおりへ飛びます（付けるより行き来するほうが回数が多いので、移動側を 2 打鍵に）。
  調べ物は往復するので、戻り先を覚えていられるのは 1 つか 2 つ。それを超えると行番号をメモに
  書き写すことになります。印は行番号の左に出ます（セッション内だけで、ファイルには何も書きません）。
- **⌘F は、前に絞っていた状態で開く（1.12.6 から）** — 漏斗（一致行だけ表示）を最後に自分で
  押した状態を覚える。構造化されたものを読む間の主目的は「一致行へ飛ぶ」より「絞る」なので、
  毎回 1 手かけて入れ直さなくてよい。漏斗を使えないペイン（構造化・JSON）では当てず、戻ったら
  当て直す。既定は off ＝ 漏斗を使っていなければ、これまでと同じに開く。
- **一致行の前後も出せる（1.12.5 から）** — `grep -C` 相当。検索バーの **`±` 欄**に行数を打つか、
  **⌥⌘] / ⌥⌘[** で 1 行ずつ広げ縮めできる。絞り込むと一致行しか残らないが、何が起きたかは
  たいてい直前の行にある。窓が重なっても行は重複せず、行番号のガターに元の行番号が出るので
  飛びは読める。値はアプリの設定として覚える（上限 100 行）。
- **構造化表示と併用できる（1.11 から）** — CSV を一致行だけに絞っても、列は揃ったまま表で読める。
  構造化中に断るのは**置換**だけ（桁揃えした見た目のまま書き換えると、見ているものと変わるものがズレるため）。
- **編集ペインでも（1.10.1 で修正）** — 8MB 未満は編集ペインで開く。そこでも ⌘F で検索・置換ができる：
  一致は全部ハイライト、⌘G / ⇧⌘G で送り（末尾で先頭へ回り込む）、置換・すべて置換（1 アンドゥ）、
  ケース維持置換まで。

**比較 / diff（v1.1 で追加）** — 表示 ▸ 比較（diff）
- 入口は 4 つ: **2 つのファイルを選ぶ**（⇧⌘D）・**開いているドキュメント同士**（未保存の本文もそのまま）・**クリップボードと比較**・**URL と比較**（https。リンクを貼れば取得して、いま開いているものと差分）。
- 左右に並べ、追加・削除・変更を色で。**変更行は行内の文字差分まで**出す（`status=200` → `500` の 1 文字が分かる）。
- **⇧⌘] / ⇧⌘[** で次/前の差分へ。**スクロールバーに差分の位置**が出るので、数百万行のどこが違うか一目で分かる。
- 列の中で選択して **⌘C** でコピー（相手側にしか無い行は混ぜない）。
- **マージ（v1.2 で追加）** — 差分の横の **→ をクリック**すると、**左の内容がその場で右へ入ります**（もう一度で取り消し。⌥→ / ⌥← でも可）。
  矢印の向きどおり、**変わるのは右**。**表示 ▸ 比較（diff）▸ マージ結果を別名で保存…** で、その右側を書き出します。
  **元の 2 つのファイルには触りません。** 何も取り込まなければ、右がそのまま出ます。
- **フォーマットを比較（v1.12.3 で追加）** — 表示 ▸ 比較（diff）▸ **フォーマットを比較**（⇧⌘F）。
  テスト環境と本番から取ったデータのように、**値は違って当たり前で、見たいのは形が揃っているか**という比べ方。
  数字は 1 桁ずつ、文字の並びは 1 個に潰してから比べるので、**値しか違わない行は「同じ」**になり、
  `2026-08-19` と `2026/08/19`、`007` と `7`、`１２３` と `123` は**違うまま残ります**。
  仮名・漢字も値として畳みますが、**全角の記号と全角スペースは形として残します**。
  入口 4 つのどれから開いても効き、**マージは自動で封じます**（形が同じ＝中身は違うので、採ると中身が消える）。
- 比較には 1 行あたり 16 バイトの索引が要る（閲覧と違い、実際にメモリを使う）。載らないサイズは
  **理由を出して断る**（黙って落ちない）。実測: 1GB × 2（871 万行）で 5.4 秒・1.7GB。

**構造化表示（v0.6 で追加）** — 読み取り専用・表示 ▸ 構造化表示 で切替
- **CSV / TSV** を等幅カラムに桁揃え、**NDJSON** はキーごとに列へ投影。
- **JSON** を字下げ整形（1.4 で追加）。再シリアライズでなく元テキストを再インデントするので、
  **キーの順序も数値の表記もそのまま**。
- 列幅はサンプルから固定するので、**数百万行でも一瞬で整形**・スクロールでもブレない。
  **東アジア文字幅対応**で全角の日本語列もピタリ揃う。
  **絞り込んでいる間は、一致行に合わせて桁を決め直します（1.12.4 から）** —— 長い値が中間にしか
  無いファイルでも、絞った結果が切れません（一致が多いときは両端 200 行ずつで測ります）。
- **桁を揃えたまま grep できる** —— 検索・フィルタ表示（live grep）・`tail -f` は構造化中もそのまま効く。
  581 万行を一致行だけに絞っても、列は揃ったまま表で読める。構造化中に断るのは**置換**だけ
  （桁揃えした見た目のまま書き換えると、見ているものと変わるものがズレるため）。
- **固定長（1.12 で追加）** — 区切り文字が無いデータは、下の桁ガイドで置いた**項目の切れ目がそのまま列**になる。
  列名は `1-8` のように桁そのもの。中身から自動判定できない唯一のモードなので、定義が無ければその場で訊く。
- **列名の帯と列幅のドラッグ（1.12.1 で追加）** — 本文の上に列名が固定表示され、300 万行目まで
  下がっても「この列が何か」が分かる。**帯の境界を掴むと列幅が変わる**（引きずっている間は線だけ、
  離したときに組み直すので巨大ファイルでも詰まらない）。
- 表示だけの変換でファイルは変更しない（保存しても元の CSV/JSON のまま）。
  有効中は **「元のテキストに戻す」** ボタン付きの帯を表示。

**桁ルーラーと固定長の項目定義（1.12 で追加）** — 表示 ▸ 桁ルーラー（⌥⌘K）
- 固定長のデータで「この項目は何桁目から何桁か」を数えるための道具。区切り文字のある形式は
  構造化表示が担うが、**固定長にはそれが効かない**。
- 本文の上に目盛りを出し、**目盛りをクリックすると任意の桁に縦線**（桁ガイド）が入る。
  **掴んで動かせる**ので、1 桁ずらすのに消して置き直す必要はない。
- 仕様書があるなら **表示 ▸ 桁の項目定義…（⇧⌥⌘K）** で `1-8,9-14,15-40` と打てる（全角の数字・カンマ・
  波ダッシュも受ける）。読めない書き方は一部だけ通さず、直してもらうまで同じシートに戻る。
- 項目定義は**ファイルごとに覚える**。開き直すと、同じ定義とルーラーのまま開く。
- そのまま **構造化表示 ▸ 固定長**へ流し込める（上記）。桁は文字数でなく**表示幅**（全角＝2）で数える。
  ルーラーを出している間は折り返さない（折り返すと 1 行が割れて桁が定まらないため）。

**桁で揃える（1.12.2 で追加）** — 線を引いたら、その場で列になる
- 引いた切れ目で**項目が 1 つおきに薄く塗られ**、そのまま列として読める。**整形しないので
  読み取り専用にならない**——固定長のデータは元から桁が揃っているので、塗るだけで表になる。
- **Tab** で次の項目の桁まで空白を詰める（後ろの字がその桁へずれる）。**⇧Tab** で戻す
  （詰めた空白だけを取り除く。字は消さない）。**タブ文字は入れない**——固定長に混ざると
  他の道具で読んだ瞬間に桁が崩れるため。
- **⌥Tab** で 2 行目以降も同じ桁割りへ。**切れ目がまだ無ければ中身から作る**（各項目の
  一番長いものが収まる幅で割る。`column -t` と同じ考え方）ので、**いきなり ⌥Tab で通る**。
- 線を**掴んで動かすと字も追いてくる**（離した時点で揃え直し。要らなければ ⌘Z）。
- **入口はどれも単独で成立する**: 打つ → Tab／いきなり ⌥Tab／目盛りをクリック／⇧⌥⌘K で数値。
  桁に触った操作はルーラーを連れてくるので、先に ⌥⌘K を押しておく必要はない。

**JSON クエリ（1.4 で追加）** — 表示 ▸ JSON クエリ…（⌥⌘J）・JSON ドキュメント上で
- **jmespath 相当の式**を打つと、結果で表示がライブに置き換わる。フィールド/ドット path（`a.b.c`）・
  配列インデックス（`items[0]`・`items[-1]`）・投影（`items[*].name`・`m.*`）・
  フィルタ（`items[?age >= 30].name`、比較 `== != < <= > >=`）。
- **揮発＝読み取り専用**。結果は保存されず、バーを閉じれば（Esc）元へ戻る。
  設定ファイルや API レスポンスの JSON（小さめ）向け。巨大ログは上の NDJSON で。

**テキスト変換ツールボックス（1.5 で追加）** — **書式**メニュー・選択に対して作用（各 1 アンドゥ）
- **ケース変換**: 大文字 / 小文字 / 各単語の先頭 / 大小反転。
- **エンコード/デコード**: URL・Base64・HTML エンティティ（デコードは不正入力を壊さず残す）。

- **外部コマンドに通す…（⌥⌘R）**: 選択を任意のシェルコマンドに通して置換 —— `jq .`・
  `sort`・`sed 's/a/b/g'`。メインスレッドを止めず、タイムアウト付き。
- **両ペインで動く**ので、10 GB ファイル内の選択にも行操作・フィルタが効く。

**外観テーマと共有（1.6 で追加）** — 環境設定 ▸ 配色
- **プリセットテーマ**: システム・Solarized Dark/Light・Monokai・**Dracula・Nord・Grass・Red Sands** ——
  本文の色と周辺 UI（サイドバー・ガター・ステータスバー）が一緒に切り替わる。

## 性能（2026-07-15 実測 / 10.00GB・86,420,337 行・日本語 UTF-8）

配布と同じ 1.7 ビルド（`swift build -c release`）、Apple Silicon で 2026-07-19 に再計測。

| 指標 | 結果 |
|---|---|
| 表示開始まで（first paint） | 45〜80ms（実行ごとに変動） |
| 全索引の構築（背景・表示はブロックしない） | 約 10 秒 |
| 末尾行へのシーク | 0.1ms |
| ファイル本体のページ | resident 3〜6GB（実行ごとに変動）・**dirty 0 バイト** |
| アプリの実メモリ | 約 145MB（何も開いていなくてもほぼ同じ・空で約 143MB） |

下の 2 行は必ずセットで読んでください。**開いた 10GB のコストは 0 です**。マップするだけで
コピーせず、`vmmap` がそのファイルに帰属させる dirty は 0 バイト —— resident なページは
ファイルバックドで、OS がいつでも捨てられます。アプリ側の約 145MB はウィンドウの描画バッファと、
10GB をマップするためのカーネルのページテーブルであって、ファイルを開いていてもいなくてもほとんど
変わらず、あなたのログではありません。索引構築中に `ps` の RSS が数 GB に見えるのも同じ理由で、
同じくらい意味がありません。

手元で再現するには:

```sh
MREDITOR_TIMING=1 .build/MrEditor.app/Contents/MacOS/MrEditor testdata/test_10gb.log
# → first paint: 61.2 ms
# → index complete: 10.24 s (86420337 lines)

vmmap $(pgrep -x MrEditor) | grep test_10gb.log     # → 10.0G  2.8G  0K  (vsize resident dirty; resident は変動・dirty は 0 のまま)
```
