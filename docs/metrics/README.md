# メトリクス

`downloads.csv` は GitHub Releases の dmg ダウンロード数のスナップショットです。
**この main ブランチには置いていません。正はブランチ
[`metrics`](https://github.com/MR-TABATA/MrEditor/blob/metrics/downloads.csv) です**（理由は下記）。
[`.github/workflows/metrics.yml`](../../.github/workflows/metrics.yml) が
[`scripts/metrics_snapshot.sh`](../../scripts/metrics_snapshot.sh) を回して1行1レコードで追記します。

撮るきっかけは3つ:

| きっかけ | いつ | 何のため |
| --- | --- | --- |
| 定時 | 毎日 03:17 UTC（12:17 JST） | 日ごとの伸びを追う |
| リリース公開 | `release: published` | **告知前の基準値**。ここが無いと「その告知で何件増えたか」が出せない |
| 手動 | Actions から `workflow_dispatch` | 告知の直後など |

なぜ撮るのか: **GitHub API は「今の累計」しか返さず、履歴を持たない。**
「あの告知で何件増えたか」は、前後で撮ったスナップショットの差分でしか出せません。

## なぜ main に置かないのか

main のルールセットは `required_status_checks`（`test` が緑であること）を要求します。
ボットの直 push には PR が無いので `test` が走らず、**構造上どうやっても通りません。**
2026-08-24 の撮影は実際にこれで落ちました（撮影自体は成功し、push だけが拒否されて
その日の分が失われた）。

bypass を開けて main を緩めるより、データを別のブランチへ出すほうを選びました。
毎日 38 行ずつ増えるデータでコードの履歴を埋めずに済む、という副次効果もあります。

## 1行目は日付でなく時刻

`taken_at` は UTC の分まで（`2026-08-23T03:17Z`）。日付で丸めると、同じ日の定時撮影と
リリース公開時の撮影がぶつかって、**後から来た方に基準値が上書きされて消えます。**
同じ日に何度撮っても全部残します（同じ分に二度走ったときだけ古い方を捨てる）。

2026-08-17 以前の行は日付だけです（当時は日単位で撮っていた）。並べ替えも突き合わせも
先頭が日付なのでそのまま通ります。

## 壊れた値を書かないための約束

スクリプトは次のどれかに触れると、**CSV を一切変更せずに終了します**（Actions は赤くなる）。

- `gh api` が失敗した。
- dmg が 0 件しか返ってこなかった。
- 前回あった版が返ってこない（ページングの取りこぼしの兆候）。
- どれかの版の数が前回より減っている（資産の貼り直しか誤取得）。

資産を貼り直したなど、減るのが正しいときは `FORCE=1` を付けて撮り直します。

## この数字が何ではないか

`download_count` は **ユニークな人数ではありません。**

- クローラやミラーのアクセスも 1 件として乗ります。
- 更新チェッカ経由で新版を取り直した既存利用者も、新しい版の 1 件になります。
- 同じ人が入れ直せばその回数だけ増えます。
- **自分の実機確認も乗ります。**

GitHub API は1回1回のダウンロードの記録を返さないので、**これらを事後に分離する材料は
ありません。** だから配布リンクのほうを、計測できる経路に通してあります。

**「◯◯人が使っています」とは書けません。**「dmg のダウンロードが累計 N 件」までが言える範囲です。

## もう一つの数字（雑音を除いたほう）

LP とリリース一覧の「ダウンロード」ボタンは、dmg へ直リンクせず
[`site/download.html` / `download.ja.html`](../../web/download.src.html) を通ります。
このページには Cloudflare Web Analytics のビーコンが入っていて、**CF が既知のボットを
弾いたうえでユニーク訪問者を数えます**（Cookie は置きません）。

数字は CF のダッシュボードで見ます（リポジトリには入りません）。経路が日英で分かれて
いるので、**日本語の告知で何件・英語で何件**がそのまま読めます。

| | 何を数えているか | 性質 |
| --- | --- | --- |
| `downloads.csv` の増分 | GitHub が返す累計の差 | **上限**。ボットも自分の確認も入っている |
| CF の `/download*.html` | ボットを弾いたユニーク訪問者 | **下限**。GitHub から直接落とす人が抜ける |

中継を通らないのは、GitHub の Releases ページから直接落とす人と、**アプリ内の更新チェッカ**
です（[`UpdateChecker.swift`](../../Sources/MrEditorCore/UpdateChecker.swift) が dmg の URL を
そのまま開く）。後者は狙いどおり ── 既存利用者の取り直しは、数えたい「新しく落とした人」では
ないので、CF 側に乗らないほうが正しい。

**この2つの差が、そのまま雑音の量です。** どちらか片方が真の値ということはありません。
公表するなら上限のほう（「dmg のダウンロードが累計 N 件」）を、上限だと分かる書き方で。

中継ページの作りと、なぜ版番号を持たせていないかは
[`web/download.src.html`](../../web/download.src.html) の冒頭に書いてあります。

## 手元で見る

ブランチ `metrics` から `.metrics/downloads.csv` へ引いてきて、その上に撮ります
（`.metrics/` は gitignore 済み）。**手元の結果は push しません** ── 見るためのもので、
記録するのは Actions です。

```sh
sh scripts/metrics_snapshot.sh            # 引いて撮って、合計・前回差分・伸びた版を表示
DRY_RUN=1 sh scripts/metrics_snapshot.sh  # 書かずに差分だけ見る
```

```sh
# 最新スナップショットの合計
git show origin/metrics:downloads.csv |
  awk -F, 'NR>1{gsub(/"/,"",$1); t[NR]=$1; v[NR]=$4; if($1>a) a=$1}
           END{for(i in t) if(t[i]==a) s+=v[i]; print a, s+0}'
```

```sh
# 版ごとの推移（1版を追う）
git show origin/metrics:downloads.csv | grep '"MrEditor-1.12.5.dmg"' |
  awk -F, '{gsub(/"/,"",$1); print $1, $4}'
```
