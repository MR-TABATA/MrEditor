The editor for text
you didn't write.

Logs. CSVs. Exports, dumps, diffs. Text that arrived from somewhere else — so you don't get to choose its size, its encoding, or how badly it is formatted. MrEditor opens it, filters it, lines up its columns, compares it, fixes it, and saves it without ever leaving the file half-written.

One file, one measurement: Japan's full corporate registry as CSV — 1.18 GiB, 5,816,535 rows, 30 columns. Measured 2026-08-03 on the shipping 1.10.2 build. Excel opens the same file and stops at 1,048,576 rows — its hard limit — taking about 60 seconds and 2.24 GB to lose 4,767,959 rows, with no warning. Numbers never opened it at all. This is not a huge-file trick: the ceiling is much higher (a 10 GB, 86,420,337-line log opens in about 80 ms and vmmap reports 0 bytes dirty for it, because the file is mapped and never copied). It is just that nothing changes as the file grows.

Structured view

Open a messy CSV. It lines up.

Switch on Structured View and CSV/TSV columns align, minified JSON pretty-prints — millions of rows, instantly. And you can still grep it: filter down to the matching rows with the columns still lined up, at any size. The formatting is view-only, so the file on disk never changes: save and you get your original back, byte for byte. Then ⌥⌘J runs a jmespath-style query in place; the result is never written. Fixed-width records line up too: drop the field boundaries on the column ruler (⌥⌘K) — or type them, 1-8,9-14,15-40 — and read them as columns.

How

The first line appears after reading a few dozen kilobytes.

Out of 10 GB. The rest is streamed in the background to build a line index, and none of it is kept in memory. Loading the whole document first — the usual approach — falls over at this size. So MrEditor does not do that.

mmap

Never load it all

The file is memory-mapped. The OS pages in only what you actually touch — so opening is near-instant at any size.

sparse index

~800 KB for 100 M lines

Keep one byte offset every 2,000 lines. Any line is a quick scan away. The whole index is tiny.

visible only

Draw a few dozen lines

A fixed-size view with a line-unit scroller — no 1.6-billion-point document view to blow past float precision.

What no one else does

tail -f a 10 GB log — and edit it.

Follow mode (⌥⌘F) tracks a growing file the way tail -f does — but it never reloads. The mmap index extends by the new bytes only, so it scales to a log that's still being written at 10 GB. Editors that tail (BBEdit, Sakura) reload the whole file; log viewers that scale to 10 GB (klogg, lnav) are read-only. Following a multi-GB log incrementally, while staying editable — we couldn't find that combination anywhere else.

New in v1.14

The log you need is on a server. Open it without downloading it.

ssh host:/var/log/app.log (⌃⌘O) opens at the tail with real line numbers, fetching only the part you look at. Filtering runs on the far side: grep -n hands back the matching lines and their numbers without transferring a byte of the file — faster than scanning locally, because nothing is sent. Follow streams tail -f and stops it over there when you stop, so nothing is left running on your server. ⌘C gives you the text, so what you found goes straight into Compare with Clipboard. Authentication is left to /usr/bin/ssh — if your terminal can reach it, so can this.

Features

Read it. Then change it.

  • Remote logs — ssh host:/path, opened at the tail without downloading. Filtering runs on the far side
  • Compare / diff — two files, two open tabs, the clipboard, or a URL. Side by side, down to the character that changed
  • Merge — click → and the left side lands in the right. Save the result; the originals are never touched
  • Edit & save, any size — small files in memory, huge files via a piece table
  • Structured view — CSV/TSV columns, NDJSON fields & JSON pretty-print, millions of rows instantly
  • Column ruler & fixed-width fields — a ruler above the text (⌥⌘K); click or drag to place field boundaries, or type them (1-8,9-14,15-40). Remembered per file, and readable as columns
  • Line text up by column — draw a guide and the text becomes columns (still editable). Tab pads to the next field, ⌥Tab applies the layout to every line — with no guides yet it derives one from the content
  • JSON query — a jmespath-style expression (⌥⌘J) filters & projects in place; the result is never saved
  • AI error diagnosis (BYOK) — select a stack trace, press ⌥⌘E, and the answer streams in as it is written. Your own key (Anthropic / OpenAI / Gemini), stored in the Keychain; pick a model — or type one that is not listed and let the connection test add it — in Settings
  • Atomic save — write to a temp file, then swap; the original is never left half-written
  • Reload on external change — fix a file elsewhere and it loads back in place, keeping your caret and scroll position. Unsaved work is never overwritten: a banner asks first. A log that only grew extends its index instead of being reopened
  • Save encoding — convert between UTF-8 / Shift-JIS / EUC-JP on save
  • Search — streams over mmap for huge files, and ⌘F works while you edit too (replace, case-preserving). Multi-term AND, regex & case toggle
  • Filtered view / live grep — show only matching lines
  • Multiple documents — open many files, switch from a sidebar
  • Session restore — reopens your sidebar on launch, unsaved drafts included
  • Recent files — File ▸ Open Recent
  • Go to line & font zoom — ⌘L, ⌘+ / ⌘- / ⌘0
  • Follow mode — tail -f (⌥⌘F); tracks a growing file incrementally, no reload, even at 10 GB
  • Copy & navigate — ⌘C, find next / previous
  • Encoding auto-detect — UTF-8 / Shift-JIS / EUC-JP
  • Color themes — System / Solarized / Monokai / custom; editor + UI
  • Fonts & display — family/size, tab width, line spacing, caret shape
  • Status bar — encoding, lines, size, index progress
  • Localized UI — English & Japanese
Pro — in preparation

Free reads one file. Pro answers the question.

Everything above stays free, and stays MIT. What is being prepared as MrkEditor (Pro) is the other half: counting, summarising, seeing time, and searching across folders — the things you currently leave the editor to do. Numbers below are measured on the shipping code (M4 Max, August 2026), not estimates.

  • Count by value — what sort | uniq -c | sort -rn does, on a column or a key=value field. 3.40 s over a 10 GB, 86,420,337-line log. Double-click a row and the document filters down to that value
  • Column stats — every column of a CSV in one pass: type, blanks, distinct, min/max, sum & average. 4.78 s for all 30 columns of a 1.18 GiB CSV (5,816,534 data rows). A column is only called numeric when every row reads as a number
  • Time histogram — when did it spike? 3.18 s over a 10 GB, 67,156,671-line log. Filter to errors first, then look at time. Lines without a timestamp are counted separately, never dropped. Drag across the bars and the document narrows to that window
  • Search across folders — 3.14 s for one literal across a single 10 GB log, on par with ripgrep. What ripgrep does not do: click a hit and the file opens at that line, and Shift-JIS / EUC-JP files are detected per file and read correctly

Not on sale yet — there is no price and no checkout on this page on purpose. When it opens, the free app will tell you from the Analyze menu.
